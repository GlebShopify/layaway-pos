LAYAWAY — Component Architecture ONE APP · 6 SURFACES · 1 LEDGER

How online + POS share one order, one ledger, one installment engine
Surfaces — app “layaway-pos” (client d396f1…)
Online Store
· theme app embed
  • “Pay With Reserve” cart link
  • Down-payment modal (10% min)
  • writes cart attrs + line props
Checkout
· function + UI ext
  • Cart Transform: reprice web cart to deposit
  • UI block: total / due today / remaining
Customer Accounts
· order status ext
  • Installment plan card + history
  • “Make a payment” → backend
  • native Pay now completes it
POS
· tile + modal ext
  • New layaway: attrs + discount(=balance)
  • Pay existing: amount → Order Edit (Direct API, backend fallback) → Collect payment
  • cancel pending payment
Admin
· app home
  • Layaway dashboard: active / outstanding / collected
  • ledger table, links to orders
Email
· native invoices
  • Order Edit commit emails the customer the amount owing + pay link
▲▼   Admin GraphQL API (Direct API from extensions · offline token from backend)  ·  AJAX Cart API (storefront)  ·  webhooks ▼
Shopify platform — the order is the product; the ledger is the truth
Cart
  • attributes: layaway_total / deposit / balance / channel…
  • line item properties (per item)
  • fixed discount (POS) · repriced lines (web)
ONE Order (deposit-shaped)
  • total = charged so far · grows per payment
  • tag layaway · note attributes
  • metafield $app:layaway.ledger (real total, paid, balance, payments, status)
  • fulfillment HOLD until balance = 0
Order Edit API
  • the installment vehicle
  • orderEditBegin → AddCustomItem(“Layaway payment #n”, $X, presentment currency) → Commit
  • setQuantity 0 = cancel pending
Payments
  • Pay now / email link = exact outstanding
  • POS Collect payment = tap-to-pay, cash, card
  • transaction posted ×N
Webhooks
  • orders/create · orders/edited
  • orders/paid · order_transactions/create
▼ HTTPS (cloudflared tunnel in demo · real hosting in prod) ▼
Layaway backend — Express, the only writer of layaway state
OAuth + sessions
  • offline admin token (SQLite)
  • scopes: read_all_orders · write_orders · write_order_edits · fulfillment holds · cart transforms
Ledger engine (syncLayawayOrder)
  • idempotent: recomputes on every webhook — never increments
  • paid = order total − outstanding · balance = real − paid
  • tags order · writes metafield · applies/releases holds at $0
Installment API
  • POST /api/layaway/:id/payment (amount, channel) → Order Edit + poll
  • POST …/payment/cancel (safe: only uncollected lines)
  • GET /api/layaway/:id → ledger (CORS for extensions)
Guards
  • amount ≤ balance · reject stacking on pending due
  • presentment currency
  • poll after orderEditCommit
① WEB DEPOSIT② POS DEPOSIT③ ONLINE INSTALLMENT④ IN-STORE INSTALLMENT⑤ RECONCILIATION LOOP
① Web deposit
modal → cart attrs → Cart Transform reprices → checkout charges deposit → order created → ⑤
② POS deposit
tile modal → attrs + discount(=balance) → normal POS sale charges deposit → same order shape → ⑤
③ Online installment
My Account card → backend /payment → Order Edit adds $X line → Pay now / email link charges $X → ⑤
④ In-store installment
POS “Pay existing” → amount → Order Edit (Direct API ▸ backend fallback) → Collect payment $X tap-to-pay → ⑤
⑤ Reconciliation
every webhook → recompute ledger from the order → update metafield → balance 0? release hold → “ships at full payoff”
